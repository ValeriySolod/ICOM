# Документація ISOM

ISOM (Information System for Property Accounting) — інформаційна система обліку майна для української установи публічного сектору. Вона підтримуватиме повний життєвий цикл державного майна: від надходження до остаточного вибуття або архівування.

Цей комплект документації — інкремент **ISOM Foundation v0.1** (пункт дорожньої карти ISOM-00). Він охоплює лише документацію та архітектуру. На цьому етапі немає програмного коду, фреймворків, залежностей, конфігурації розгортання чи схеми бази даних.

## Правила оформлення

- Документація ведеться українською мовою. Англійською залишаються:
  - назви файлів і каталогів;
  - ідентифікатори (`BR-*`, `LEG-*`, `ISOM-*` тощо);
  - назви сутностей доменної моделі (`Asset`, `CustodyAssignment`);
  - назви операцій (`approveTransfer()`).

  Ці назви стануть ідентифікаторами в коді.
- Кожен документ починається з блоку метаданих: **Статус**, **Версія**, **Оновлено**.
- Статуси документів: `Чернетка`, `На розгляді`, `Затверджено`, `Замінено`.
- Префікси ідентифікаторів:

| Префікс | Значення | Де визначено |
|---|---|---|
| `AP-nn` | Архітектурний принцип | system-context.md |
| `AD-nn` | Архітектурне рішення | system-context.md |
| `OQ-nn` | Відкрите питання / невирішений пункт | документ, де воно виникає |
| `FR-xxx-nn` | Функціональна вимога | functional-requirements.md |
| `NFR-nn` | Нефункціональна вимога | non-functional-requirements.md |
| `BR-nn` | Бізнес-правило | business-rules.md |
| `LEG-nn` | Нормативне джерело | legislation-register.md |
| `SEC-nn` | Вимога безпеки | security-requirements.md |
| `DC-n` | Рівень класифікації даних | data-classification.md |
| `ISOM-nn` | Інкремент дорожньої карти | roadmap.md |

- Ідентифікатори ніколи не використовуються повторно. Вилучені пункти позначаються `Вилучено` і зберігають свій ідентифікатор.
- Діаграми — Mermaid у блоках коду, щоб вони зберігалися в системі контролю версій як текст.
- Ключові слова вимог: **має / повинен** — обов'язкова вимога, **слід** — рекомендація, **може** — необов'язкова можливість.

## Джерела вимог

Остаточні вимоги до ISOM визначаються такими джерелами (у порядку пріоритету):

1. Чинне законодавство України.
2. Публічні відомчі нормативні акти, зокрема акти Державної служби спеціального зв'язку та захисту інформації України (Держспецзв'язку).
3. Внутрішні відомчі документи, надані замовником. Частина з них може мати обмежений доступ.
4. Затверджене технічне завдання.

Ця документація є **основою**. Вона не замінює юридичної експертизи. Кожне посилання на нормативний акт позначено як таке, що потребує офіційної перевірки юристами або замовником до промислової експлуатації.

## Майбутнє технічне завдання

> **Статус: ще не надано.** Офіційне технічне завдання (ТЗ) на ISOM ще не отримано.

Коли ТЗ буде надано, його потрібно зіставити з наведеними нижче артефактами. Це треба зробити до того, як будь-який інкремент реалізації почне на нього спиратися.

| Артефакт | Дія зіставлення |
|---|---|
| [Доменна модель](docs/architecture/domain-model.md) і [сутності](docs/data/entities.md) | Зіставити кожну вимогу ТЗ до даних із сутністю. Зафіксувати нові сутності або атрибути. |
| Архітектурні рішення (`AD-*` у [system-context.md](docs/architecture/system-context.md)) | Підтвердити, змінити або замінити кожне рішення через явну зафіксовану зміну. |
| [Матриця відповідності](docs/compliance/compliance-matrix.md) | Додати ідентифікатори вимог ТЗ як джерела трасування. |
| [Вимоги безпеки](docs/compliance/security-requirements.md) | Зіставити положення ТЗ щодо безпеки з `SEC-*`. Зафіксувати розбіжності. |
| [Процеси](docs/workflows/) | Узгодити описи процесів у ТЗ із задокументованими процесами. |
| [Дорожня карта](docs/roadmap/roadmap.md) | Перепланувати інкременти відповідно до обсягу та пріоритетів ТЗ. |

**Правило конфліктів.** Якщо ТЗ суперечить наявній правовій вимозі, вимозі відповідності чи безпеки в цій документації, наявну вимогу **не можна** мовчки перезаписувати. Кожен конфлікт потрібно:

1. внести до журналу конфліктів ТЗ нижче;
2. передати на розгляд замовнику, юристам і/або службі безпеки;
3. вирішити задокументованим рішенням із зазначенням особи, яка його ухвалила, та підстави.
