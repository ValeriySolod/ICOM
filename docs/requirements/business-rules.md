# Бізнес-правила

**Статус:** Чернетка · **Версія:** 0.1 · **Оновлено:** 2026-10-02

Бізнес-правила забезпечуються в доменному та прикладному шарах (AD-09), ніколи — лише в інтерфейсі. Правила, позначені як *налаштовувані*, задаються конфігурацією політик для організації, категорії майна чи варіанта процесу.

## Цілісність і простежуваність

| ID | Правило | Джерело |
|---|---|---|
| BR-01 | Статус, розташування, закріплення за МВО та вартість майна змінюються **лише** через перевірені бізнес-операції. Загального оновлення полів немає. | AP-01, AP-02, AD-01 |
| BR-02 | Кожна господарська операція має документальну підставу. Це документ дозволеного типу в стані, що дозволяє проведення. *Налаштовується* для кожного типу операції. | AP-03, LEG-01, LEG-06, LEG-07 |
| BR-03 | Кожна суттєва зміна створює подію аудиту (AuditEvent) у тій самій транзакції, що й зміна. | AP-04 |
| BR-04 | Документ, що брав участь у проведеній операції, не можна фізично видалити через жоден звичайний процес застосунку. | AP-08, LEG-13 |
| BR-05 | Майно, передачі, інвентаризації, списання, документи та записи аудиту фізично не видаляються. Вони переходять у стан «Скасовано», «Замінено», «Визнано недійсним» або «Архівовано». Перехід фіксує причину, виконавця, час і, де застосовно, документальну підставу. | AP-08 |
| BR-28 | Кожна операція фіксує і **дату проведення**, і **час внесення запису**. Внесення операції заднім числом понад налаштовану межу або в закритий обліковий період потребує дозволу уповноваженої особи. | AP-02 |

## Розподіл обов'язків

| ID | Правило | Джерело |
|---|---|---|
| BR-06 | Для операцій, на які поширюється розподіл обов'язків: `Initiator != Approver` (ініціатор ≠ особа, що затверджує). Перелік таких операцій і обмеження *налаштовуються*. | AP-05 |
| BR-07 | Автор розбіжності за інвентаризацією не може затвердити відповідне облікове коригування. | AP-05, LEG-08 |
| BR-08 | Ініціатор справи списання не може затвердити цю справу. | AP-05, LEG-10 |
| BR-26 | Ролі технічних адміністраторів за замовчуванням не мають доступу до бізнес-даних. Будь-яке надання доступу має бути явним, за можливості обмеженим у часі та аудитованим. | AD-11, LEG-15 |

## Майно, розташування та закріплення

| ID | Правило | Джерело |
|---|---|---|
| BR-09 | У кожен момент часу одиниця майна має не більше одного чинного основного закріплення (CustodyAssignment). | AD-03 |
| BR-10 | Закріплення не редагується після набрання чинності. Зміна закриває поточне закріплення й відкриває нове, кожне з документальною підставою. | AD-03, AP-08 |
| BR-11 | ПІБ МВО не зберігається текстом у записі майна. Майно посилається на закріплення, а закріплення — на ResponsiblePerson. | AD-03, LEG-12 |
| BR-12 | Розташування майна — посилання на вузол ієрархії розташувань, а не довільний текст. | AD-04 |
| BR-13 | Одна одиниця майна має один центральний обліковий запис. Інвентарний номер унікальний у налаштованих межах (межі — OQ-14). | AP-01 |
| BR-30 | Зміни вартості (виправлення первісної вартості, переоцінка, залишкова вартість) фіксуються лише через операції оцінки з документальною підставою, як історія AssetValuation. | LEG-01, LEG-03 |
| BR-31 | Кожна одиниця майна має облікову класифікацію. Щонайменше:<br>- основні засоби<br>- інші необоротні матеріальні активи<br>- запаси<br>- окрема категорія<br>- на відповідальному зберіганні<br>- тимчасово передане<br>- списане<br>- отримані матеріали<br><br>Класифікація визначає застосовні правила. | LEG-02 … LEG-05 |

## Переміщення та передача

| ID | Правило | Джерело |
|---|---|---|
| BR-22 | Вид передачі визначає потрібні документи, погодження та обмеження розподілу обов'язків (*налаштовується*). Передача між установами та зовнішня передача потребують правової підстави згідно із застосовним актом. | LEG-09 |
| BR-23 | Тимчасова передача має очікувану дату повернення. Прострочене повернення позначається. | — |
| BR-24 | Майно в ремонті залишається на балансі. Його закріплення та розташування під час ремонту відстежуються, а передача в ремонт і повернення з ремонту оформлюються окремими документами. | LEG-06 |

## Інвентаризація

| ID | Правило | Джерело |
|---|---|---|
| BR-14 | Сканування та фізична перевірка **ніколи** не змінюють безпосередньо офіційних облікових залишків, статусу, розташування чи закріплення. | AD-05, LEG-08 |
| BR-15 | Результати інвентаризації впливають на облікові записи лише через затверджені коригувальні документи. Їх оформлюють після звіряння, отримання пояснень і формального рішення. | AD-05, LEG-08 |
| BR-21 | Поки на майно діє інвентаризаційне блокування, конкурентні операції заборонені або потребують явного дозволу згідно з політикою. Конкурентні операції — передача, списання, передача в ремонт. | AD-05 |

## Списання

| ID | Правило | Джерело |
|---|---|---|
| BR-16 | Списання — це справа. Майно отримує статус «Списано» лише після завершення облікового етапу затвердженої справи списання. | AD-06, LEG-10 |
| BR-17 | Процес списання обирається за схемою `Asset Category -> Applicable Regulation -> Applicable Workflow`. Якщо для категорії процес не налаштовано, списання **заблоковано**. Процес за замовчуванням не передбачається. | AP-07 |
| BR-18 | Матеріали, отримані після розбирання або утилізації, оприбутковуються як нові облікові одиниці. Кожна з них пов'язана зі справою списання, з якої походить. | LEG-04, LEG-10 |
| BR-29 | Для категорій, що регулюються внутрішніми або обмеженими документами, характеристики з обмеженим доступом не зберігаються, доки замовник не визначить режим. | LEG-22 |

## Документи, підписи, зберігання

| ID | Правило | Джерело |
|---|---|---|
| BR-27 | Кожен документ має категорію зберігання. Знищення можливе лише після дати набуття права на знищення, за затвердженою процедурою, і сам факт знищення фіксується. | LEG-19, LEG-20, LEG-21 |
| BR-32 | Типи документів, їхні шаблони та процеси — це конфігурація. Зміни типових форм вносяться як нові версії шаблонів. Наявні документи зберігають версію шаблону, за якою їх створено. | AD-07, LEG-06, LEG-07 |
| BR-34 | Якщо тип документа вимагає кваліфікованого електронного підпису, документ не може перейти до стану «Підписано» без чинного підпису. Діє після ввімкнення КЕП. | AD-12, LEG-14 |

## Аудит, ідентифікація, персональні дані

| ID | Правило | Джерело |
|---|---|---|
| BR-19 | Вміст QR-коду чи штрихкоду — лише непрозорий ідентифікатор, без захищених даних. | AP-09, AD-10 |
| BR-20 | Розпізнавання відсканованого ідентифікатора потребує автентифікації. Дані, що повертаються, фільтруються за правами доступу. | AD-10 |
| BR-25 | Записи аудиту не можна редагувати чи видаляти через звичайний інтерфейс або звичайним адміністраторам. | AD-08 |
| BR-33 | Персональні дані МВО обмежено тим, що потрібно для кожного процесу. Доступ надається за службовою потребою і журналюється. | LEG-12 |
